# flock 락과 idempotent 자동 실행 설계

자동 실행 스크립트는 "새 터미널을 열 때 서버가 없으면 하나 띄운다"는 단순한 규칙을 수행한다. 하지만 모바일 터미널에서는 같은 규칙이 동시에 여러 번 실행되기 쉽고, 한 번 띄운 서버가 오래 살아남아야 한다. 이 문서는 그 두 문제를 어떻게 풀었는지 설명한다.

## 동시 실행 경쟁

UserLAnd에서는 터미널을 여러 번 열 수 있고, 앱이 재시작되면 여러 세션이 거의 동시에 `.bashrc`를 실행할 수 있다. 서버가 떠 있는지 확인하고 시작하는 사이에 두 세션이 모두 "없음"으로 판단하면 `serve`가 두 번 호출된다. Orca 자체가 같은 프로필의 중복 serve를 exit 3으로 막지만, 그보다 앞에서 한 번만 시도하도록 만드는 편이 깔끔하다.

그래서 스크립트는 `orca-autostart.lock.v2` 파일을 fd 9으로 열고 `flock -n 9`으로 비블로킹 락을 잡는다. 락을 못 잡은 세션은 조용히 끝난다. 이렇게 하면 동시에 열린 터미널 중 하나만 시작 로직을 통과한다. 락 파일 이름에 `v2`가 붙은 이유는 이전 락 파일(`orca-autostart.lock`)과 구분하기 위해서다. 경로는 [경로와 버전 레퍼런스](../reference/paths-and-versions.md)에 정리되어 있다.

## 자식 fd 상속 버그

여기서 미묘한 문제가 하나 생긴다. fd 9으로 잡은 flock 락은 fork된 자식에게 그대로 상속된다. 서버는 오래 살아남는 프로세스이므로, 락을 든 채로 백그라운드에 남으면 이후에 열리는 모든 자동 실행이 영구히 락을 못 잡고 아무 일도 하지 못한다. 겉으로는 "서버가 안 뜬다"처럼 보인다.

이를 막기 위해 nohup 줄에 `9>&-`를 붙여 분리된 자식에서 fd 9를 닫는다.

```sh
nohup setsid --fork "$ORCA_SERVE_BIN" serve --refuse-public --pairing-address 127.0.0.1 \
    </dev/null 9>&- >>"$LOG_FILE" 2>&1 &
```

락은 시작을 직렬화하는 용도이고, 서버가 살아 있는 동안은 필요하지 않다. 자식에서 닫아도 racy한 시작은 이미 방지되어 있으므로 안전하다. 이 한 줄이 없으면 두 번째 터미널부터 자동 실행이 조용히 실패한다. 증상이 나타나면 [서버가 안 뜰 때 진단하기](../how-to/diagnose-server-not-starting.md)에서 로그를 확인한다.

## 상태 기반 idempotency

락은 동시성을 막지만, 이미 서버가 떠 있는지는 별개로 봐야 한다. 스크립트는 `orca status --json`으로 현재 프로필을 서비스 중인 서버가 있는지 묻는다. 이 명령은 아무것도 시작하지 않고 상태만 알려준다. `"running": true`이면 PID를 뽑아 `existing <pid>`를 출력하고 끝난다. 아니면 `started`를 출력하고 서버를 시작한다.

`.bashrc` 블록은 이 출력을 받아 `Orca: 기존 서버 사용 (pid ...)` 또는 `Orca: 서버를 새로 시작했습니다`로 바꿔 보여주고, 이어서 `pairingUrl` 한 줄을 출력한다. 출력이 대화형 셸에만 나오는 것도 같은 이유다. 서버를 멈추거나 재시작하지 않고 상태만 보고 링크만 다시 보여주는 것이 목적이기 때문이다([UserLAnd/PRoot 환경](userland-proot.md)의 터미널 특성 참고).

## 분리와 안전 장치

서버는 `setsid --fork`로 새 세션을 만들고 `nohup`으로 SIGHUP을 무시하며 `stdin`을 `/dev/null`로 돌린다. 터미널을 닫아도 서버가 같이 죽지 않고 터미널의 pts/stdout을 붙잡지도 않는다. stdout과 stderr는 `orca-autostart.log`에 덧붙여진다.

마지막으로 스크립트는 절대 기존 서버를 죽이거나 재시작하거나 시그널을 보내지 않는다. Orca가 중복 serve를 거부하는 exit 3을 최후의 안전망으로 두고, 그 앞에서 상태 검사와 락으로 중복을 막는다. 그래서 여러 번 터미널을 열어도 PID는 그대로이고 로그에는 `already serving ... no action`만 쌓인다. 이 동작을 끄는 방법은 [자동 실행 끄기·되돌리기](../how-to/disable-autostart.md)에 있다.
